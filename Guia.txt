Guía práctica para el desarrollo de un sistema web con Spring Boot, Thymeleaf y Oracle

Autonomous Database

En el desarrollo de aplicaciones modernas, especialmente en entornos
empresariales y educativos, es fundamental comprender cómo integrar distintas
tecnologías para construir soluciones completas, escalables y mantenibles. Esta
guía tiene como propósito enseñar paso a paso la construcción de una aplicación
web utilizando Java con Spring Boot, el motor de vistas Thymeleaf y una base de
datos Oracle Autonomous Database en la nube, conectada mediante el uso de
wallet de seguridad.
Spring Boot es un framework del ecosistema de Spring que permite desarrollar
aplicaciones Java de manera rápida y estructurada. Su principal ventaja es que
simplifica la configuración inicial del proyecto, evitando la necesidad de
configuraciones manuales extensas, lo que permite al desarrollador enfocarse
directamente en la lógica del negocio. Spring Boot sigue una filosofía basada en
“convención sobre configuración”, lo que significa que el framework asume
configuraciones por defecto inteligentes que pueden ser modificadas solo cuando
es necesario.
Desde el punto de vista arquitectónico, Spring Boot promueve el uso del patrón de
diseño en capas. Esto implica que la aplicación se divide en componentes bien
definidos: la capa de presentación (controladores), la capa de lógica de negocio
(servicios), la capa de acceso a datos (repositorios) y la capa de persistencia
(entidades). Esta separación permite que el sistema sea más ordenado, escalable
y fácil de mantener, ya que cada parte cumple una función específica.
Por otro lado, Thymeleaf es un motor de plantillas que permite generar vistas
dinámicas en aplicaciones web. A diferencia de otros enfoques donde el frontend
está completamente separado, Thymeleaf se integra directamente con Spring Boot
y permite construir interfaces web utilizando HTML tradicional, pero con
capacidades dinámicas. Esto significa que se pueden mostrar datos provenientes
de la base de datos, iterar listas, manejar formularios y generar contenido dinámico
directamente en el servidor.
El funcionamiento conjunto entre Spring Boot y Thymeleaf sigue un flujo claro:
cuando el usuario accede a una URL desde el navegador, el controlador en Spring
Boot recibe la solicitud, procesa la lógica necesaria (generalmente a través de un
servicio), obtiene los datos desde la base de datos mediante un repositorio, y
finalmente envía esos datos a una vista Thymeleaf. Thymeleaf renderiza la
información en HTML y la envía de vuelta al navegador del usuario. Este modelo se
conoce como arquitectura MVC (Modelo-Vista-Controlador).
En cuanto a la base de datos, se utiliza Oracle Autonomous Database, que es una
solución en la nube altamente segura y automatizada. Este tipo de base de datos
gestiona de forma automática aspectos como el rendimiento, la seguridad, los
respaldos y la disponibilidad. La conexión a esta base de datos se realiza mediante
un wallet, que es un conjunto de archivos de configuración y certificados que
permiten establecer una conexión segura mediante protocolo TCPS, evitando la
exposición de credenciales sensibles.

El uso de Spring Data JPA en el proyecto permite abstraer la interacción directa con
la base de datos. En lugar de escribir consultas SQL manuales para cada operación,
el desarrollador puede utilizar repositorios que ya incluyen operaciones CRUD
(crear, leer, actualizar y eliminar), lo que reduce la complejidad del código y mejora
la productividad. Además, JPA se encarga de mapear automáticamente las tablas
de la base de datos a clases Java, lo que facilita el manejo de los datos dentro de
la aplicación.
Esta guía, por tanto, no solo busca enseñar a crear un sistema funcional, sino
también a comprender cómo se integran estas tecnologías en un entorno real. A lo
largo del proceso, se construirá un sistema completo con múltiples tablas
relacionadas, operaciones CRUD y una interfaz web funcional, permitiendo al
estudiante o desarrollador adquirir una visión clara del desarrollo de aplicaciones
web modernas con Java.
Finalmente, es importante destacar que el enfoque utilizado en esta guía es
progresivo. Se inicia con la configuración del entorno, luego se establece la
conexión con la base de datos, posteriormente se modelan las entidades y se
implementa la lógica del sistema, y por último se construyen las vistas web. Este
orden permite comprender cada componente antes de integrarlo, facilitando el
aprendizaje y reduciendo errores comunes en el desarrollo.

Sistema de capas en Spring Boot
Spring Boot trabaja bajo una arquitectura por capas, lo cual significa que la
aplicación no es un solo bloque de código, sino que está organizada en niveles
donde cada uno cumple una función específica. Esto no es solo “orden”, es una
forma de evitar dependencias innecesarias y facilitar mantenimiento, pruebas y
escalabilidad.
En su proyecto, las capas funcionan así:
Primero está la capa de presentación (Controller).
Esta es la que “habla” con el usuario. Cuando alguien entra desde el navegador a
una URL como:
http://localhost:8080/cintas
Spring Boot envía esa petición al controlador correspondiente. El controlador
interpreta la solicitud, decide qué hacer y qué vista devolver.
Luego está la capa de servicio (Service).
Aquí es donde vive la lógica del sistema. Por ejemplo, validaciones, reglas de
negocio, combinaciones de datos, etc. El controlador no debería tener lógica
compleja; solo delega al servicio.

Después está la capa de acceso a datos (Repository).
Esta capa se encarga de interactuar con la base de datos. Gracias a Spring Data
JPA, usted no necesita escribir SQL para operaciones básicas, porque el repositorio
ya tiene métodos como:
findAll()
findById()
save()
deleteById()
Finalmente está la capa de persistencia (Entity).
Son las clases que representan las tablas de la base de datos. Por ejemplo, su tabla
CINTAS se convierte en una clase Cinta. Spring usa estas clases para mapear
automáticamente datos entre la base de datos y el código Java.
El flujo completo funciona así:
El usuario hace una petición → el Controller la recibe → el Service procesa la lógica
→ el Repository consulta la base → se devuelven los datos → el Controller los envía
a la vista → Thymeleaf genera el HTML → el navegador lo muestra.
Este flujo es el corazón del modelo MVC (Modelo – Vista – Controlador).

Cómo funciona Spring Boot internamente
Spring Boot usa lo que se llama Inyección de Dependencias. Esto significa que
usted no crea manualmente los objetos, sino que Spring los crea y los conecta
automáticamente.
Por ejemplo, cuando usted escribe:
@Service
public class CintaService { ... }
y luego en el controlador:
private final CintaService service;
Spring automáticamente “inyecta” ese servicio. Esto evita que usted tenga que
hacer new CintaService() y permite que el sistema sea más flexible.
Además, Spring Boot detecta automáticamente las clases anotadas con:
@Controller
@Service

@Repository
@Entity
y las registra como componentes del sistema.

Sistema de etiquetas en Thymeleaf
Thymeleaf funciona sobre HTML, pero agrega atributos especiales llamados
“atributos Thymeleaf”. No cambia el HTML, lo extiende.
Por ejemplo, este HTML es normal:
<td>Texto</td>
Pero con Thymeleaf:
<td th:text="${cinta.estanteria}"></td>
Aquí pasa algo importante:
${cinta.estanteria} es una expresión que viene desde el backend.
El controlador envía un objeto al modelo:
model.addAttribute("cintas", lista);
Thymeleaf toma esa información y la inserta en el HTML antes de enviarlo al
navegador.
Algunos atributos importantes:
th:text → reemplaza el contenido de la etiqueta
th:each → recorre listas (como un for)
th:href → genera enlaces dinámicos
th:action → define a dónde se envía un formulario
th:object → vincula un formulario con un objeto Java
th:field → enlaza campos del formulario con propiedades del objeto
Ejemplo clave:
<tr th:each="c : ${cintas}">
<td th:text="${c.codigoCinta}"></td>
</tr>
Esto es equivalente a un ciclo for, pero en HTML.

Cómo funciona la navegación en Thymeleaf
La navegación en Thymeleaf no es “cliente” como en React, es completamente del
lado del servidor.
Cuando usted hace esto:
<a th:href="@{/cintas}">Ir a cintas</a>
Thymeleaf genera:
<a href="/cintas">Ir a cintas</a>
Cuando el usuario hace clic:
El navegador hace una nueva petición HTTP → Spring Boot la recibe → el
Controller responde → Thymeleaf genera otra página → el navegador la
reemplaza completamente.
Esto se llama navegación tradicional basada en servidor.
No hay JavaScript manejando rutas como en SPA (Single Page Applications), sino
que cada acción recarga la página completa.

Cómo funcionan los formularios con Thymeleaf
Aquí es donde más valor tiene.
Ejemplo:
<form th:action="@{/cintas/guardar}" th:object="${cinta}" method="post">
<input type="text" th:field="*{estanteria}" />
<button type="submit">Guardar</button>
</form>
Esto hace varias cosas automáticamente:
th:object vincula el formulario con un objeto Java
th:field conecta cada input con un atributo del objeto
Cuando se envía el formulario, Spring convierte automáticamente los datos en un
objeto Java
Y en el controlador:

@PostMapping("/guardar")
public String guardar(@ModelAttribute Cinta cinta) {
service.guardar(cinta);
return "redirect:/cintas";
}
Spring recibe el formulario y lo convierte en un objeto Cinta sin que usted tenga
que parsear nada manualmente.

Spring Boot organiza el sistema en capas separadas para mantener orden y
escalabilidad.
Thymeleaf permite generar HTML dinámico desde el servidor usando atributos
especiales.
El navegador nunca ve Thymeleaf, solo recibe HTML ya procesado.
Cada acción del usuario genera una petición nueva al servidor.
Los datos fluyen desde la base de datos → backend → Thymeleaf → HTML →
navegador.

Ejemplo basado en base de datos VideoClub

Primeramente, es necesario crear la base de datos en Oracle Autonomous
Database dentro de Oracle Cloud, ya que será el entorno donde se almacenará toda
la información del sistema.
Para ello, debe ingresar a Oracle Cloud (https://cloud.oracle.com) con su cuenta
institucional o personal. Una vez dentro, diríjase al menú principal y seleccione la
opción de “Oracle Database” y posteriormente “Autonomous Database”.
En esta sección, deberá crear una nueva base de datos. Para hacerlo, presione el
botón “Create Autonomous Database” y complete la información solicitada. Como
pasos generales:
Debe asignar un nombre a la base de datos, por ejemplo “videoclub”.
Seleccione el tipo de carga de trabajo “Transaction Processing” (ATP), ya que es el
más adecuado para aplicaciones web.
Configure el usuario administrador (ADMIN) y establezca una contraseña segura.
Puede dejar los valores de CPU y almacenamiento en la configuración básica
(Always Free o según su entorno).
Finalmente, presione “Create Autonomous Database” y espere a que el servicio esté
disponible.
Una vez creada la base de datos, el siguiente paso fundamental es descargar el
wallet, el cual permite establecer una conexión segura entre la aplicación y Oracle
Cloud.
Para descargar el wallet, ingrese nuevamente a la sección de Autonomous
Database, seleccione la base de datos que acaba de crear y ubique la opción “DB
Connection”. Dentro de esta opción encontrará el botón “Download Wallet”.
Al presionar “Download Wallet”, el sistema le solicitará definir una contraseña para
proteger el archivo comprimido. Esta contraseña es obligatoria y se utilizará
posteriormente para acceder a los archivos del wallet. Una vez definida, descargue
el archivo ZIP.
Después de la descarga, debe descomprimir el archivo. Se recomienda colocarlo
en una ruta sencilla y sin espacios para evitar problemas de configuración. En esta
guía se utilizará la siguiente ruta:
C:/wallet/videoclub

Dentro de esta carpeta encontrará varios archivos importantes como tnsnames.ora,
sqlnet.ora, cwallet.sso, entre otros. Estos archivos contienen la configuración
necesaria para que la aplicación pueda conectarse de forma segura a la base de
datos.
Es importante asegurarse de que esta ruta coincida exactamente con la configurada
en el archivo application.properties del proyecto Spring Boot, específicamente en el
parámetro TNS_ADMIN.
Con estos pasos completados, la base de datos estará lista y el entorno preparado
para establecer la conexión desde la aplicación web desarrollada con Spring Boot.

Paso 4. Configurar la conexión con Oracle Autonomous
Aquí está una de las partes más importantes. Usted ya tiene el wallet en:
C:/wallet/videoclub
No va a usar el CONNECT_STRING largo tipo (description=...) dentro del código
Java. En Spring Boot con wallet, lo correcto es usar el alias del servicio que viene
dentro de tnsnames.ora del wallet. Oracle documenta ese formato de URL con
TNS_ADMIN.
Abra el archivo:
C:/wallet/videoclub/tnsnames.ora
Ahí verá algo parecido a esto:
videoclub_high =
(description=...)
videoclub_medium =
(description=...)
videoclub_low =
(description=...)
O tal vez el alias tenga otro nombre, pero debe usar exactamente el alias del
tnsnames.ora.
Ahora edite src/main/resources/application.properties así:

spring.application.name=videoclubweb
server.port=8080
spring.datasource.url=jdbc:oracle:thin:@videoclub_high?TNS_ADMIN=C:/walle
t/videoclub
spring.datasource.username=ADMIN
spring.datasource.password=SU_CLAVE_REAL
spring.datasource.driver-class-name=oracle.jdbc.OracleDriver
spring.jpa.hibernate.ddl-auto=none
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.database-platform=org.hibernate.dialect.OracleDialect
spring.thymeleaf.cache=false
logging.level.org.hibernate.SQL=DEBUG
logging.level.org.hibernate.orm.jdbc.bind=TRACE
Si en su tnsnames.ora el alias no se llama videoclub_high, cambie ese valor por el
alias real.
También revise el archivo sqlnet.ora del wallet. Debe seguir apuntando al wallet,
pero si el zip ya vino bien configurado, normalmente no hay que tocarlo.

Paso 11. Crear servicios simples

Para arrancar rápido, los servicios pueden ser muy sencillos. Le muestro uno
completo y luego repite el patrón.
CintaService.java
package com.videoclub.videoclubweb.service;
import com.videoclub.videoclubweb.entity.Cinta;
import com.videoclub.videoclubweb.repository.CintaRepository;
import org.springframework.stereotype.Service;
import java.util.List;
@Service
public class CintaService {
private final CintaRepository repository;
public CintaService(CintaRepository repository) {
this.repository = repository;
}
public List<Cinta> listar() {
return repository.findAll();
}
public Cinta obtener(Integer id) {
return repository.findById(id).orElse(null);
}
public Cinta guardar(Cinta cinta) {
return repository.save(cinta);
}
public void eliminar(Integer id) {
repository.deleteById(id);
}
}

Paso 13. Controladores para las tablas intermedias
Aquí lo más práctico es usar formularios con listas desplegables para elegir IDs ya
existentes.
CintaPeliculaController.java
package com.videoclub.videoclubweb.controller;
import com.videoclub.videoclubweb.entity.Cinta;
import com.videoclub.videoclubweb.entity.CintaPelicula;
import com.videoclub.videoclubweb.entity.CintaPeliculaId;
import com.videoclub.videoclubweb.entity.Pelicula;
import com.videoclub.videoclubweb.repository.CintaPeliculaRepository;
import com.videoclub.videoclubweb.repository.CintaRepository;
import com.videoclub.videoclubweb.repository.PeliculaRepository;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;

@Controller
@RequestMapping("/cinta-pelicula")
public class CintaPeliculaController {
private final CintaPeliculaRepository relationRepository;
private final CintaRepository cintaRepository;
private final PeliculaRepository peliculaRepository;
public CintaPeliculaController(CintaPeliculaRepository
relationRepository,
CintaRepository cintaRepository,
PeliculaRepository peliculaRepository)
{
this.relationRepository = relationRepository;
this.cintaRepository = cintaRepository;
this.peliculaRepository = peliculaRepository;
}
@GetMapping
public String listar(Model model) {
model.addAttribute("relaciones", relationRepository.findAll());
return "cinta_pelicula/lista";
}
@GetMapping("/nuevo")
public String nuevo(Model model) {
model.addAttribute("cintas", cintaRepository.findAll());
model.addAttribute("peliculas", peliculaRepository.findAll());
return "cinta_pelicula/formulario";
}
@PostMapping("/guardar")
public String guardar(@RequestParam Integer codigoCinta,
@RequestParam Integer codigoPelicula) {
Cinta cinta = cintaRepository.findById(codigoCinta).orElse(null);
Pelicula pelicula =
peliculaRepository.findById(codigoPelicula).orElse(null);
CintaPeliculaId id = new CintaPeliculaId();
id.setCodigoCinta(codigoCinta);
id.setCodigoPelicula(codigoPelicula);
CintaPelicula relacion = new CintaPelicula();
relacion.setId(id);
relacion.setCinta(cinta);
relacion.setPelicula(pelicula);
relationRepository.save(relacion);
return "redirect:/cinta-pelicula";
}
@GetMapping("/eliminar")
public String eliminar(@RequestParam Integer codigoCinta,
@RequestParam Integer codigoPelicula) {
CintaPeliculaId id = new CintaPeliculaId();
id.setCodigoCinta(codigoCinta);

id.setCodigoPelicula(codigoPelicula);
relationRepository.deleteById(id);
return "redirect:/cinta-pelicula";
}
}
